# TensorFold Worker source experiment

This package supplies a separately selected, default-off Worker backend. It embeds TensorFold Scheduler raw chunks in one Node-owned Worker PID and reuses Orchard's gRPC service, detokenizer, tool parser and events. The historical package path retains `http`; no HTTP child is launched. The normal MLX runtime and its lockfiles remain unchanged. The trusted public Controller dispatch path is available only under explicit default-off Controller and Node profile configuration.

`orchard-worker-tensorfold --experimental-tensorfold --backend tensorfold --profile-file <local-profile.json> --socket-path <owned-socket>` is the explicit executable boundary. Node Agent remains the process owner; Controller must act through Node Agent. The committed source-dev wrapper `bin/orchard-worker-tensorfold` adds the experiment flag and the `ORCHARD_TENSORFOLD_WORKER_PROFILE_FILE` profile to the Node's Worker arguments and execs the venv entrypoint, so the Node still owns the Python process. `ORCHARD_WORKER_BACKEND=tensorfold` selects it in source dev; see the [source-dev guide](../../docs/local-dev.md#tensorfold-experiment-source-dev). Prefix caching and observe/enforce memory sampling are disabled for this experiment; generation is stream/C1. The positive legacy prefix-cache entries hint supplied by Node is accepted as inert; only the frozen driver configuration controls TensorFold checkpoints. Existing socket paths are refused, and cleanup removes only the inode created by this executable.

The local JSON configuration has exactly three objects:

- `profile`: every `ExperimentProfile` field in `admission.py`, including exact model/version/artifact/template/tokenizer-config identities and projection/token/output/deadline limits.
- `bounds`: every `DriverBounds` field in `tensorfold_driver.py`, including fixed working/workspace/copy/checkpoint/buffer capacities and cancellation/settlement limits.
- `native`: `model_path`, `max_bundle_files`, `max_bundle_bytes`, and `prefill_step`.

There are intentionally no invented hardware bounds or model identities in an example configuration. Token/context/vocabulary limits must agree across profile and driver, and the profile deadline cannot exceed the driver deadline. Copy reservations conservatively charge a full qualified working-cache capacity and the same transient capacity before materialization. Those capacities require later native qualification; accounting reservations do not measure physical GPU allocation.

Native assembly is lazy and requires an isolated tuple: TensorFold 0.6.6 (Git commit `cb2ebf0540f42604e2759b2ddef497861e928248`), MLX 0.32.3, MLX-LM 0.32.0, Transformers 5.14.1. The optional `native` extra pins that tuple for Apple Silicon: `mise exec -- uv sync --locked --directory native/orchard_tensorfold_http --extra native`. The default install stays model-free, and the extra does not advance the foundation pins, supply weights, admit a model or prove hardware safety. A later plain `uv sync` removes the native packages. The loader verifies a bounded full artifact-tree digest and bound template/config snapshots, refuses custom/remote architecture configuration, and admits only the frozen Qwen3.5 family with the Qwen3 Coder parser. The tokenizer declaration must name a file in the model entrypoint directory, matching the frozen TensorFold loader; separate tokenizer layouts are refused. Sampling uses the admitted temperature/top-p, disables provider top-k/min-p defaults and ignores ambient seed salt; greedy requests use the provider's `None` convention. Full bundle verification can extend cold startup. Runtime provision and actual native load remain qualification work.

The explicitly configured Node preparation gate on the owned Worker socket reads the maximum-4096-byte `tensorfold_profile_admission_json` status offer after load, verifies the selected binding, and supplies it with unmodified natural `messages`/`tools` in internal `tensorfold_history_projection_json`. Ordinary public metadata and generic capabilities cannot authorize that field. It is outside preparation redemption, which the bridge rejects. The bridge rerenders prompt and no-generation-suffix history and requires exact authoritative bytes/IDs before Scheduler submission. Explicit structured prior reasoning fields remain rejected; opaque assistant content is preserved. Thinking/medium and legacy-blended output are the only admitted profile.

Successful completion follows a positive engine-thread settlement barrier. Uncertain native work, buffer/output overflow, deadline expiration, abandoned streams or shutdown quarantines the incarnation and denies reuse while keeping custody. An independent deadline watchdog works without consumer pulls. Normal settled unload joins both Scheduler threads and retires the driver without pretending that the process was reaped. Only the external Node owner can confirm owned process-tree exit/reap and start a replacement. A failed cache copy logs one warning with the custody reason and a byte, lease and checkpoint snapshot, and each request logs its cached, prompt and retained-checkpoint counts when its first output arrives. These lines carry no request content.

Model-free tests exercise real Orchard event/tool mapping, current protobuf wire encoding and local gRPC/UDS against fake native assets, plus copy custody, token buffers, checkpoint reuse, cancellation and shutdown. Synthetic sizes/latencies are test values only. No native memory-fit, GPU drain, supported-foundation, model-quality or public-route claim follows from those results. Full application/database checks and separately authorized hardware qualification remain required before a production handoff.

## Trusted Controller and Node selection

Both applications read `:tensorfold_experiment_profile` from their own application configuration; absence (`nil`) keeps the route off. Source dev loads them from the JSON files named by `ORCHARD_TENSORFOLD_CONTROLLER_PROFILE_FILE` and `ORCHARD_TENSORFOLD_NODE_PROFILE_FILE`. The Controller map and the Node map independently contain string keys `schema_version` (1), `profile_id`, `model_id`, `version`, `artifact_sha256`, `template_sha256`, `tokenizer_config_sha256`, `enable_thinking` (true), `reasoning_effort` (`medium`), `output_projection` (`legacy_blended`) and `max_projection_bytes`. Version and all digests are exact lowercase 64-hex identities. Profile/model names are bounded to 256 bytes; the projection ceiling is 1 MiB and the chosen value must also match the Worker profile's bound. The Controller additionally requires `authorized_node_ids` (a nonempty bounded list). The Node may set `offer_timeout_ms` (1–1000 ms); lookup is further capped by the request's remaining absolute deadline. No sample artifact identity or hardware capacity is implied by these configuration keys.

Controller selection requires the existing exact registry's explicit rendered medium contract. Omitted effort and other tiers retain their ordinary semantics outside the selected model and are refused for this experiment, rather than relabeled. Seed, stop sequences, JSON response mode, explicit tool choice and global live cache affinity are unsupported in the selected profile. `tool_choice` "auto" with declared tools is the default and is admitted on both sides; the bridge accepts it only with a non-empty tool list. Authoritative token IDs, resolved tools and opaque canonical messages are retained. The IDs come from the rendered-effort tokenizer helper's whole-prompt encoding without added special tokens. The Controller refuses a selected request without them, and dispatch keeps them whatever `tokenizer_safe_mode` is set to. Optional profile `max_request_seconds`, `max_input_tokens`, `max_output_tokens` and `max_context_tokens` let the Controller refuse a deadline or token count this bridge would reject, before dispatch. The bridge logs each admission rejection's code and fixed reason, never request content. The bridge applies the same shared contract5 history normalization as Orchard's tokenizer, including developer/text-part history, nil assistant tool-call content and object-decoded function arguments; it rejects structured prior reasoning and duplicate argument keys. The Node offers no fallback to a stock Worker for a supplied experimental projection.

Each dispatched attempt must use an authorized target, then obtain a fresh loaded offer through Node preparation before Accepted. Node retains the exact original request and bound projection for start and rejects altered redemption. Unload/restart or another Node requires a new offer; the native backend independently compares incarnation at admission. Generic Worker status, heartbeats, public metadata and model capability discovery grant no experiment authority. Model-free tests of these boundaries do not qualify actual GPU settlement or Node-owned process reaping.
