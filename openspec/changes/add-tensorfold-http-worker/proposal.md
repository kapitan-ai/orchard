## Why

A full-history provider needs natural tool continuations and checkpoint reuse while retaining Orchard's authoritative token IDs and Node Agent lifecycle ownership. Passing rendered text as a user message loses the history boundary.

## What Changes

- Prepare an explicitly selected, default-off TensorFold Worker executable with isolated dependencies; retain the default MLX-LM implementation and its locks.
- Gate the additive versioned ExecuteInferenceRequest projection on exact tokenizer-only parity with canonical natural tool history.
- Bind loaded model, artifact, template, effort and Worker incarnation; reject unsupported controls and mixed-version routes.
- Bound admission, streaming buffers and retained/staged state. Keep uncertain cancellation unavailable until confirmed owned process-tree reaping.

## Impact

SPEC.md §7.2's existing experimental qualification profile excludes selecting TensorFold as an Orchard runtime foundation from its results. This candidate remains a separately selected, default-off source experiment; it changes neither that prohibition nor the supported foundation. SPEC.md §3.4's opaque assistant content and rejection of structured prior reasoning remain in force. The historical change identifier retains `http`, but the implementation embeds Scheduler raw chunks inside the existing Node-owned Worker PID: stock HTTP parsing loses closing markers and newlines. No public dispatch route, GPU execution, distribution or publication is included. Source feasibility does not qualify native execution or promote a runtime foundation.
