# Design: server-enforced read-only cluster role

## Status and authority

Proposed; Najib has accepted the need for a role, not the detailed choices below. [Headless Q3 and task 3.3](../define-headless-deployment/tasks.md#3-open-items-outside-this-change) are the prerequisite decision. Current `SPEC.md` §10.4 still has exactly four roles. Nothing in this package grants runtime authority before acceptance, SPEC reconciliation, implementation, and verification.

## Identity and additive authority

Use the name **`cluster_reader`** (display: **Cluster Reader**). The existing RoleBinding is the only grant: `principal_type = service_account`, `principal_id = API Client ID`, `role = cluster_reader`, `tenant_scope_id = nil`. The API Token authenticates its enabled owner; it does not carry an independent attenuated role. The API Client can still belong to a Workspace for inventory/provisioning purposes; that ownership does not make this grant tenant-scoped.

Do not grant this role to a Tenant, API Key, Console Identity, or Portal User. A tenant-scoped row is invalid, not a narrower version of the role. Keep ADR 0004's Admin API boundary. Extend ADR 0007 only for the explicitly enumerated Operator reads; a reader cannot enter the entire Operator pipeline and thereby reach writes.

**Grants remain additive**, as required by [the accepted credential-management policy](../cross-surface-authorization-contract/specs/credential-management/spec.md#requirement-credential-authority-is-scoped-to-full-target-privilege). ADR 0033 establishes the shared authority boundary and agent deferral, not this additive rule. Combining `cluster_reader` with `operator` or `admin` on the same API Client preserves the latter's permissions and full response projections while those grants remain sufficient at delivery. Similarly, a retained `inference_client` grant still admits inference and makes the principal more than read-only. Do not label any such client or token read-only. This avoids deny-precedence rules that change existing administrator/operator permissions.

For each management request by a principal with a valid `cluster_reader` grant, use the **reader path** when the principal lacks independently sufficient existing cluster `operator` or `admin` authority for that action, whatever other grants it holds. All reader admission/refusal, projection, side-effect and leadership rules below apply to that path, including for reader-plus-inference clients. Independently sufficient existing authority retains its existing behavior; a reader grant cannot supplement an operator grant to authorize an Admin action. “Reader-only” describes dedicated provisioning and truthful display, not execution-path selection.

For the reader-only provisioning mode, require a dedicated API Client whose complete retained owner-plus-token grant union is either empty (new client) or only the identical cluster-reader grant. Reject other grants, including inactive-token grants and unknown future roles; never strip or replace existing grants. All tokens of that owner share its authority. A later authorized grant addition can broaden it; no token-level restriction is claimed. Future MCP work must use dedicated credentials and account for current owner authority, not infer safety from issuance history or the selected tool list.

The reader grant does not authorize inference, Console sessions, Portal operations, bootstrap, or Runtime Endpoint operations. Public unauthenticated liveness/CA endpoints retain their own contracts and confer no additional authority.

## Current route admission

This table is exhaustive for current GET routes under `/ops/v1`, `/admin/v1`, and `/metrics`. **Admit** means the later implementation must produce the exact closed reader projection below, not expose today's response unchanged. **Refuse** means a request on the reader path receives the existing role-required 403 before target lookup. Independently sufficient existing operator/admin authority retains its current behavior.

| Method and route | Reader-path decision | Content / projection boundary | Leadership |
| --- | --- | --- | --- |
| `GET /ops/v1/health` | Admit | Bounded health/build/check statuses and counts; omit runtime messages, names, targets, diagnostics, and remediation text | Any Controller; existing readiness 200/503 semantics |
| `GET /ops/v1/cluster` | Admit | Deployment/role/lock status, timestamps and closed caller authority; omit raw leadership error text | Any Controller; report its own evidence under the narrow Standby exception below |
| `GET /ops/v1/nodes` | Admit | Node IDs, lifecycle/admission/health/freshness and scheduling status, summary counts; no arbitrary maps or free text | Active; existing 503 standby/unproven gates |
| `GET /ops/v1/nodes/:node_id` | Admit | Same bounded status for one Node, validated agent version and capacity with counterfactual/phase/freshness labels; decision code/time only; omit names, addresses, capabilities, tool readiness, raw diagnostics and memory-budget detail | Active; existing 503 gates |
| `GET /ops/v1/worker-recovery/nodes/:node_id/models/:model_id` | Admit | Node UUID, revision, state, booleans and stable reason code; omit runtime model name and version/epoch strings from returned evidence; caller must already know catalog Model UUID and exact version | Active; existing 503 gates; required `version` query remains; no hydration |
| `GET /ops/v1/scheduler/explanations/:request_id` | Admit | Typed request/Node IDs, tier, numeric score and stable reason codes only; omit arbitrary candidate diagnostics/components and target references; request ID comes from outside this role | Active for reader-path calls; see leadership rationale below |
| `GET /ops/v1/circuit-breakers/nodes/:node_id` | Admit | Existing closed breaker presenter: IDs, state, counts, timestamps, generation | Active; existing 503 gates |
| `GET /ops/v1/circuit-breakers/placements/:node_id/:model_id` | Admit | Same closed breaker presenter, with model ID; caller must already know Model UUID | Active; existing 503 gates |
| `GET /admin/v1/node-admission/candidates` | Refuse `admin_required` | Raw inventory/compatibility maps, observed identity, decision reason/metadata and actor/audit references; admin-only | Refuse before leadership or lookup |
| `GET /admin/v1/node-admission/candidates/:candidate_id` | Refuse `admin_required` | Same candidate/decision content as list | Refuse before leadership or lookup |
| `GET /metrics` | Refuse `operator_required` | Site-local exposition includes canonical raw tenant labels; §9.1 forbids carrying tenant/user dimensions into external metrics egress | Refuse before scrape |

**Initial inspection coverage, not autonomous monitoring discovery.** A dedicated reader can list Node UUIDs, then inspect their health, capacity and Node breakers. It cannot discover catalog Model UUIDs or exact versions: Admin models are denied and `/v1/models` needs independent inference authority. Recovery status and placement breakers therefore require preconfigured targets; scheduler inspection requires an incident request ID supplied externally. For example, a monitor reads cluster authority, lists Nodes, checks a degraded Node by UUID and its Node breaker, then uses an operator-supplied `(Node UUID, Model UUID, version)` inventory to inspect recovery and the placement breaker. If an incident supplies a request ID it can inspect the bounded scheduler explanation, but cannot fetch the request body or discover other requests. Missing inventory or incident IDs end that branch of the journey; do not widen the token to make discovery work. Add an end-to-end acceptance test for this journey.

Raw `/metrics` remains denied under §9.1. A site-local Prometheus scraper still needs an `operator` (or admin) token today, with that role's write authority. Name **tenant-dimension-free aggregate telemetry** as an eligible future read below: queue depth, request/error rates, latency and capacity. Its contract must aggregate compatible series correctly, not merely delete tenant labels. This proposal adds no endpoint. A reader role does not itself authorize external egress of even admitted operational metadata.

**Residual disclosure:** the admitted reads expose cross-tenant operational metadata: Node/Model/Request IDs, resource existence, scores, reason codes and changing counts. Fixed errors and closed fields do not provide traffic-analysis protection or eliminate all timing/existence inference. Najib must accept that disclosure separately from content exclusion.

### Closed reader projections

Use explicit recursive field and value validation, not key-only dropping from arbitrary JSON. Every admitted reader data response, including readiness-derived health 503, adds top-level `projection: "cluster_reader.v1"` and a reader-specific `contract_version`. These two mandatory metadata fields are in addition to each closed domain-field list below. Root versions are `orchard.cluster_reader.<shape>.v1`, with `<shape>` exactly `health`, `cluster_status`, `node_status_list`, `node`, `worker_recovery`, `scheduler_explanation`, or `circuit_breaker`. Never retain the full operator object's version for a reduced object. Nested objects that already carry `contract_version` receive `orchard.cluster_reader.<shape>.v1` with `<shape>` `control_plane_status` or `node_status`; unversioned nested maps/array entries inherit the enclosing reader schema. The top-level projection applies recursively; do not insert arbitrary markers into nested maps. Removed, renamed or retyped reader fields require a new reader version. Refusal/error envelopes remain the existing fixed error shapes, not data projections.

Each reader projection must be a recursive field subset of the same route's shared Controller-owned operator builder output. Extend that shared builder's fact output with the declared schema metadata and cluster `authority` metadata so readers do not invent separate domain facts; existing full operator/admin wire presenters retain their current bodies and field values. Schema-version values intentionally differ by representation; retained domain values must agree for the same fact snapshot. Apply closed presenters to shared typed facts, and skip omitted probes rather than fetch unsafe data merely to redact it. Regression fixtures must compare the reader with that route's builder, including nested paths, not a separately reconstructed reader model. This subset test proves provenance and consistency, not disclosure safety: the closed schema, recursive value validation and malicious-field regressions establish the disclosure boundary. Do not add `?projection=`: adapter tests use a reader-provisioned API Client. Admission and schema selection depend on current server-resolved authority, never caller projection, role or scope flags.

- **Health:** `version`, `build_ref`, `build_date`, `status`, `checks`, `readiness_contract`, `reason`, and `runtime` only. Build values come from Controller build metadata: validate `version` against the canonical product-version grammar or the existing literal `dev` fallback, `build_ref` as a 40-character lowercase hexadecimal Git SHA or literal `unknown`, and `build_date` as a canonical ISO date. Omit `build_channel`: its build-time override accepts arbitrary text, not a closed vocabulary. `checks` and readiness order use only server-declared check names/status enums; `readiness_contract` retains only its fixed `version` and declared `check_order`. `reason` is a declared readiness code. Runtime contains only declared `status`, UUID `node_id`, declared `worker_state`, declared `health`, and nonnegative integer `counts.active_requests` / `counts.loaded_models`, retaining null for unavailable evidence. No `runtime.message`, display name, diagnostics, raw error, transport metadata, or remediation payload.
- **Cluster:** retain `object`, reader-versioned `contract_version`, `summary`, and `control_plane`, but only `deployment_mode`, `controller_role`, `advisory_lock_status`, `lock_age_ms`, `last_renewed_at`, and fixed `object` / reader-versioned `contract_version` under `control_plane`. Omit both Controller identity strings, `standby_write_path_behavior`, and `last_observed_leadership_error`. Summary has its existing three enum fields. Add top-level `authority` containing exactly `roles` (sorted unique declared role names from the complete current owner-plus-token grant union) and `read_only` (true only when that union contains solely the valid cluster-reader assignment). No grant scopes, Tenant IDs, credential IDs or arbitrary names. Unknown/unclassifiable grants fail closed rather than yield true. Compute this under transmission-admission fences, not from cached issuance data. The projection marker is not proof of read-only authority: reader-plus-inference gets the same shape with `read_only: false`. Self-inspection describes current grants, not permanent token attenuation or a guarantee about the next request.
- **Nodes:** list retains `object`, reader-versioned `contract_version`, `data`, and `summary` with total/state/health counts. Each status contains only fixed `object`/reader-versioned `contract_version`, UUID `resource.id` and fixed `resource.type`, `lifecycle.state`, `admission.category/source/latest_decision`, `health.status`, `freshness.status/observed_at/source`, `scheduling.eligible/reason_codes`, and the labeled `dispatch_capacity` subset below, validated against declared vocabularies. Detail retains `object`, UUID `id`, `state`, `health`, `agent_version`, `last_heartbeat_at`, `inserted_at`, `updated_at`, that reduced `status`, and `latest_decision` containing only fixed `object`, declared `decision`, and `decided_at`. `agent_version` must be a bounded canonical version under the existing product-version grammar, otherwise null; no arbitrary build prose. It is available on detail, not invented on list where the operator builder does not supply it. Nodes are identified by UUID only; hostnames and display names remain excluded. No unused memory-budget probe runs.
- **Worker recovery:** retain only `key.node_id`, `revision`, `state`, `hydrated`, `eligible`, and `reason` from validated `WorkerRecoveryEvidence`, additionally validating the Node UUID against the resolved target identity. Omit `key.model_id`: it is the catalog record's free-form runtime model name, not the catalog UUID in the route. The caller already supplied that UUID; do not return another model identifier or redefine the operator field. Valid non-UUID runtime names must still permit successful reader inspection. The input version still selects the exact placement; it is not echoed. Do not return checkpoint bodies, last command/reason, epoch strings, raw failures, or other recovery records.
- **Scheduler:** retain `request_id`, `selected_node_id`, `selection_tier`, and the three candidate arrays. Each candidate retains only UUID `node_id`, boolean `eligible`, declared `tier`, finite numeric `score` or null, and declared `reason_codes`. Validate public request IDs rather than copying arbitrary persisted strings. No `target_ref`, `components`, `diagnostics`, supplemental prose, cache-affinity key, request payload, or output. Reject invalid required values with the existing `scheduler_explanation_invalid` 422, without `details: inspect(reason)` for readers.
- **Breakers:** retain only `object`, `kind`, `node_id`, `model_id`, `state`, `contribution_count`, `opened_at`, `suppressed_until`, `last_cleared_at`, and `generation`, with canonical IDs, enums, numbers and timestamps. No clear reason or audit payload.

The Node status `dispatch_capacity` map retains these numeric fields: `runtime_concurrency_enforcement_limit`, `controller_dispatch_ceiling`, `effective_dispatch_limit`, `controller_accounted_allocation`, `dispatch_headroom`, `placement_headroom`, `available_slots`, `legacy_pre_cutover_limit`, `legacy_pre_cutover_reported_allocation`, `legacy_pre_cutover_claim_count`, and `legacy_pre_cutover_available_slots`. Values must be finite nonnegative integers or null where the shared builder permits missing evidence; never coerce text or missing facts into zero. Alongside them retain exactly these interpretation fields from the same snapshot:

- `mode` (fixed `counterfactual`), `counterfactual` (true), and `consumers_ready` (false), preserving this diagnostic builder's existing observational meaning even when the durable phase is enforcing;
- `authority_phase` (`pre_cutover`, `enforcing`, `invalid`), `policy_state` (`shadow_legacy`, `approved_explicit`, `enforcing`, `missing`, `invalid`), `management_class` (`production_managed`, `unmanaged_source_development`, `unmanaged_compatibility`, `missing`, `invalid`), and `authority_decision` (`legacy_pre_cutover`, `f11_enforcing`, `unmanaged_source_development`, `unmanaged_compatibility`, `fail_closed`);
- boolean `eligible`, canonical UTC `observation_time` or null, and `reason_codes` from the shared declared capacity vocabulary, including `runtime_capacity_observation_stale` and `node_heartbeat_stale`. These reason labels and the observation time preserve capacity freshness evidence; Node heartbeat freshness alone must not attest fresh capacity. Missing time stays null, not the response time; a missing snapshot remains null.

This is the explicit reader serialization exception to main `dispatch-capacity` **Counterfactual Capacity Diagnostics** and SPEC §4.6.2, not a change to the shared evaluator or full operator/admin diagnostics. Preserve the evaluator's zero canonical enforcing values under `legacy_pre_cutover`, separate `legacy_pre_cutover_*` evidence, and missing-policy/fail-closed reasons. Neither a number nor `eligible` reserves or authorizes dispatch. Do not return `placement_capacity` maps, raw capacity evidence or policy prose; do not relabel a counterfactual snapshot as live enforcing capacity. Invalid interpretation fields fail closed rather than leave unlabeled numbers.

For reader recovery inspection, a well-formed unknown Model UUID, inactive model or wrong exact version returns the same `404 worker_recovery_target_not_found` and fixed message. Do not disclose the existing operator distinction between unknown model (404) and catalog version mismatch (422). Missing/malformed required inputs may retain `422 invalid_worker_recovery_command`; operator/admin behavior is unchanged.

Absent nullable evidence remains null; it is not inferred from unsafe text. Optional unclassified fields are omitted. Invalid required evidence fails with the route's existing unavailable/invalid envelope and a fixed message, never raw inspected terms. New output fields require explicit reader classification and regression coverage before exposure. The safety invariant applies to error bodies and nested values as well as successful responses.

**String provenance audit:** existing shared structures are not disclosure validators. Recovery key strings are only bounded/nonblank; `NodeStatus` accepts string-map values; Node detail's source record stores `agent_version` as a string; and `SchedulerExplanation` normalizes IDs/tiers as strings. Reader presenters must independently check canonical UUIDs (including selected/candidate Node IDs), public Request IDs, declared state/tier/source/reason vocabularies, product versions and canonical timestamps, never pass through those domain strings merely because the builder accepted them. The build-channel override is another free-form source and is excluded above. Breaker Model IDs are catalog UUIDs, unlike recovery runtime names. Closed schemas and malicious-field tests cover these distinctions while preserving valid nullable evidence and existing full operator/admin output.

### Every current mutation is refused

| Method and route | Reader-path refusal |
| --- | --- |
| `POST /ops/v1/requests/:id/retry` | 403 `operator_required` |
| `POST /ops/v1/worker-recovery/nodes/:node_id/models/:model_id` | 403 `operator_required` |
| `POST /ops/v1/circuit-breakers/nodes/:node_id/clear` | 403 `operator_required` |
| `POST /ops/v1/circuit-breakers/placements/:node_id/:model_id/clear` | 403 `operator_required` |
| `POST /admin/v1/node-admission/candidates/:candidate_id/reject` | 403 `admin_required` |
| `POST /admin/v1/node-admission/candidates/:candidate_id/clear-rejection` | 403 `admin_required` |
| `POST /admin/v1/nodes/:node_id/admit` | 403 `admin_required` |

Use `AdminErrorHelpers`' existing `{"error":{"code":...,"message":...}}` envelope, with no target details. Preserve the current role-required messages for those refusals. Missing/invalid/expired/revoked credentials retain `401 invalid_api_key`. A valid token with a disabled owner still authenticates but receives the surface's existing 403 (`operator_required` or `admin_required`), as does an authenticated principal without the required binding. Authentication and route authorization precede controller target lookup, body-dependent action handling, leadership checks, preview, and mutation. Transport/media/body-parser failures retain their pre-authentication behavior; malformed HTTP is not promised a role error.

All other mutating management actions, including specified future POST/PATCH/PUT/DELETE operations, refuse requests on the reader path. Examples include Node cordon/uncordon/drain/maintenance/resume/decommission, request cancel, diagnostics generation, Controller retire, capacity-policy changes/cutover, governance, model import/lifecycle, credential creation/revoke/rotation, identity provisioning and invitation, enrollment and bootstrap-token creation. Neither `dry_run: true` nor explicit confirmation changes the decision. Action Preview remains domain-side-effect-free, but it is authorization for a proposed write and may disclose write-only information; the reader does not receive it. This is a permission classification, not a claim that previews mutate.

Do not implement `method == GET` as the authorization policy. Explicit method plus resolved route/action is required. New routes default-deny this role; aliases, HEAD dispatch, method overrides, wildcard routes, and query/body flags must not create implicit access. Keep existing 404/405 behavior for unsupported paths/methods without reaching a domain operation; reader-path `/metrics` requests remain refused at its authorization boundary.

The eligible future reads are not automatically authorized when a route appears. Their implementing changes must add explicit server actions, bounded projections, active-leader enforcement and tests, update this matrix or its synced successor, and reconcile affected contracts including dispatch-capacity's operator/admin-only wording. ## Provisioning, storage and Console

Extend the existing Controller-host command with **`orchardctl api-clients bulk-provision --access-level cluster_reader`**. The only accepted option values initially are `inference_client` (default, preserves current behavior) and `cluster_reader`; it is not a general role-grant CLI. Keep the existing CSV schema, single-organization validation, dry-run/apply modes, rotation semantics and mandatory protected one-time output. Organization/owner contact remain inventory requirements, not authority scopes. Do not add implicit admin/operator provisioning or a new endpoint.

Reader mode creates/ensures the cluster grant **instead of** calling `ensure_inference_client_access/3`. Revalidate the complete owner/token grant union inside the apply transaction, including rotation and concurrent grant insertion; dry-run is not authority for later apply. Reject a mixed-authority existing client with a row/field validation error before any batch writes, and recheck on apply with rollback of the whole batch on conflict. Omitted/default mode must reject an existing reader-only client rather than silently attach inference authority. Existing non-reader provisioning behavior is unchanged. An intentional broader grant uses the separately authorized grant-management path, not an implicit conversion through this mode.

Dry-run and apply summaries include `access_level: cluster_reader` and `scope: cluster`, and state that all tokens inherit current owner grants. Output remains protected one-time delivery; no secret in stdout, logs, errors, or audit. Grant provisioning records the existing RoleBinding grant audit and existing batch/token events atomically with changes; use the existing schema, not invented preview/read audit payload fields.

Migration inventory:

- Add `cluster_reader` to `RoleBinding`'s Ecto enum/type and the PostgreSQL `role_bindings_role_check` currently allowing four strings. Use a new migration, not edits to historical migrations.
- Add a role-specific check enforcing `role <> 'cluster_reader' OR (principal_type = 'service_account' AND tenant_scope_id IS NULL)`. Preserve `role_bindings_principal_type_check`, including the pending compatible `console_identity` extension, and `role_bindings_inference_client_tenant_scope`.
- Retain `idx_role_bindings_unique_assignment` and the partial null-scope `idx_role_bindings_unique_cluster_assignment`; they already prevent duplicate cluster assignments. No cross-role exclusivity constraint: unions are intentionally additive.
- No default grant/backfill or promotion of existing clients. Gate provisioning until all serving Controllers and retained governance/CLI readers and writers understand the new role. Old Ecto enums can fail on new rows. Rollback must revoke/disable reader credentials and explicitly remove reader bindings under authorized audited custody before removing the role value; never auto-delete grants or start an incompatible binary against them.

The existing Workspace API Client Access display currently distinguishes only Inference Client versus No Access. Show Cluster Reader and cluster scope for this grant; never display No Access for a valid reader. Show all effective relevant roles and **Not read-only** when inference/operator/admin or any other grant is retained. This is metadata display for already-authorized Console operators, not Console login or a new grant editor. No reader bearer authorizes the Console. Follow `docs/DESIGN.md` and verify narrow/wide layouts in the later implementation; no native mobile surface is added.

## Audit, leadership and side effects

Successful reads on the reader path must not insert/update domain rows, audit rows, candidates, admission decisions, observations, queue/capacity sources, recovery checkpoints, or breaker state. The sole durable bookkeeping exception is API Token `last_used_at`, updated after authentication but before authorization, including refusals and requests to Standby. It is evidence of token use, not successful access; it must neither extend expiry nor advance the credential's revocation-relevant revision. Coarsening this steady polling write is a named follow-up, not part of this proposal. Keep existing authentication-failure audit behavior for invalid credentials; it is not a successful-read exception or a new authorization-denial audit.

Today there is no per-principal denial audit: `orchard_http_requests_total` records aggregate endpoint/method/status, including `status="403"`, without actor or resolved action. Accept that visibility limitation here. A separate **bounded denial logging** follow-up may record authenticated actor, resolved server action and fixed reason, never raw targets, bodies or credentials. Logging remains non-authoritative, cannot grant access, and must not invent successful mutation audits. Passive request metrics/logging retain existing secret exclusions.

`OperatorHealth.evaluate/0` currently calls `snapshot(timeout: ...)`; the default `OrchardConsole.Runtime.snapshot/1` observes Node state. Reader health must explicitly use the existing non-observing path (`observe?: false`) end to end, including authenticated BEAM/mTLS verification and rejection. Reader Node detail can skip the omitted memory-budget probe; do not fetch content just to redact it later. Audit worker-recovery connect/inspection, breaker inspection and all reader failure paths for observation, hydration, reconciliation or capacity-clearing side effects. Use status-only/non-observing operations or refuse unavailable evidence; no implicit repair is allowed.

Reader breaker inspection must use a non-locking committed-state read, never `CircuitBreakers.inspect`'s dispatch-serializing target `pg_advisory_xact_lock` or target row write locks. Dispatch's `evaluate_many` uses that same advisory key today. Common caller-authority fences remain mandatory, but must not include dispatch target locks for inspection. The result is observational and may race with a clear/dispatch; it cannot reserve eligibility. Test that a held dispatch lock does not block reader inspection.

Current `InspectWorkerRecoveryPlacement` hydrates cold keys under §12.2.3 and the accepted Runtime Endpoint contract. The reader path must instead use status-only already-hydrated evidence with the same typed identity/freshness validation, or return `503 worker_recovery_unavailable` without hydration/epoch claim/checkpoint mutation. Add this explicit exception to the contract, not a hidden change to existing operator or scheduler hydration. No new external route is needed.

Health and cluster report serving-Controller evidence on Standby, without claiming active authority; readiness may still be 503. Other admitted reads are active-only. Current Node/recovery/breaker gates are retained. Scheduler explanation currently has no explicit leadership gate; add it for the reader path because it reads durable Request state under the accepted `operator-command-authority` target. Do not silently change existing operator/admin scheduler behavior in this slice. A later complete family migration reconciles all callers under its own scope. Use the existing `503 controller_standby` and `503 controller_leadership_unproven` envelopes after successful authorization; do not let leader failure replace a 403 on a forbidden route. Reads must not acquire leadership, renew it, or trigger reconciliation just to answer.

The contract reconciliation must explicitly exempt only reader health/cluster from §10.11.2's active-Controller family-operation requirement: their purpose is observing the serving Controller, including an unhealthy Standby, not operating on a managed target. The self-authority summary concerns only the authenticated caller. They still require authoritative Postgres, current caller/credential/grant checks and the same shared authority fences; no replica, cached-authority or local Repo fallback is allowed. Unavailable authority returns `503 authority_unavailable`, not cached health/cluster success. This exception does not extend to credential-family inspection or any other reader route, and must be named alongside §§2.5 and 11.9's durable-operation boundary.

At transmission admission reselect both execution path and projection under the shared fences for every request that entered with a reader grant, even if operator/admin authority initially selected a full body. If those stronger grants disappear while the reader grant survives, never send the fetched full body merely because the GET remains permitted. Discard it and rebuild on the newly authorized reader path, including non-observing execution and current leadership, or refuse without data. Rebuilding must pass transmission admission again. On Standby, a downgraded scheduler read returns `503 controller_standby`; a health rebuild uses the non-observing path. Previously performed operator-authorized effects cannot be undone, and already admitted bytes cannot be recalled.

Provisioning, grant changes, disablement and revocation remain writes under their existing actor/audit/leadership authority, not reader privileges. A reader-bearing API Client is a retained **cluster-privileged target** under §10.11's complete owner-plus-key grant classification, including when disabled or all tokens are expired. A tenant administrator must not inspect/revoke it by treating a reader as inference-only; cluster-admin management remains available.

## Alternatives and risks

- **Operator token plus GET tool list:** rejected; the token still authorizes writes.
- **Every GET:** rejected; Admin decisions, request evidence and metrics have disclosure risks, and health GET currently observes state.
- **Deny-precedence reader ceiling:** not proposed because a reader grant would override otherwise sufficient operator/admin authority, changing established additive authorization. Dedicated provisioning and truthful effective-authority display are proposed instead; an authorized grant manager can intentionally broaden a client later.
- **Exclusive reader grant assignment:** a separate alternative could reject additions that combine reader and incompatible grants without changing existing operator/admin authorization. This would require an explicit conversion policy for clients changing between reader and broader authority, plus constraints and atomic checks across every retained grant writer. Additive assignment remains the proposed default; exclusivity is a product-owner choice, not a deny-precedence rule.
- **New token kind or per-token scope:** deferred; not needed for a coarse cluster RoleBinding, and not equivalent to the existing API Client model.
- **Assume operational JSON is safe:** rejected; nested maps and strings require value validation and negative tests. The reduced projections trade diagnostic richness for a small, reviewable disclosure boundary.

## Questions for Najib before acceptance

The proposal and deltas use these concrete defaults; a different answer requires revising them before implementation:

1. Accept the name `cluster_reader` and API-Client-only cluster scope (rather than a human Console read role)?
2. Accept these three independent boundaries?
   - **(a) Route authorization:** no Admin, content-bearing reads or previews; raw `/metrics` remains denied.
   - **(b) Coverage:** eight initial inspection reads, with externally supplied Model UUID/version and incident request IDs, not comprehensive autonomous monitoring. Bounded placement inventory and tenant-dimension-free aggregate telemetry are named eligible follow-ups, not new routes here. Future Controller/capacity-policy reads remain gated on their own contracts.
   - **(c) Residual disclosure:** permit cross-tenant operational IDs, existence, scores, reason codes and changing counts, with no traffic-analysis protection?
3. Accept additive grants with dedicated reader-only bulk provisioning, current-authority self-inspection and explicit Not read-only display? The cost is that read-only is a property of the current grant set, not of the token; self-inspection mitigates mistakes but is not lasting attenuation. Exclusive assignment instead rejects incompatible additions without overriding otherwise sufficient grants, but requires conversion policy and constraints across retained grant writers that are not fenced yet. A deny-precedence ceiling would separately change authorization of sufficient grants.
4. Accept contract-first sequencing, activation blocked on cross-surface tasks 3.1–3.2, the stated fenced-reader versus plug-time operator baseline, and the narrow fenced health/cluster Standby exception? Plug-time parity requires an explicit revision before implementation, not an implementer shortcut.

No unresolved choice is delegated to the implementer. Contract acceptance, implementation authorization, independent review, publication, and merge remain separate gates.
